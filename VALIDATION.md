Validated on Windows on 2026-10-10 using Rust and Bevy 0.19.1. The dependency versions are pinned in `rewrite/Cargo.lock`.

Tests cover old/new display defaults, need selection, suppressed dialogue, actual Tractor Beam pull and cancellation when held input leaves the world, Launch Pad cap/expiry/launch, flock cohesion/separation/force caps, and rotating gravity with signed Low/Zero Gravity combinations. Review found stale Tractor Beam input and ignored configured gravity strength/sign; both were fixed and regression-tested.

Pet Cage validation covers saved position, care stations clamped inside, continued eating/drinking, release, and 720 actual simulation steps with a strong initial impulse and every body part remaining inside the cage, followed by dragging/portal/rotating-gravity stress and every-frame script positioning. Review caught scripts escaping after the original physics-only constraint; the shared script runner now reapplies confinement for both one-shot and every-frame scripts.

Expanded classic and desktop native probes save thirteen views each, including need dialogue/lights, opt-in corner stats, Launch Pad, new modes, cage confinement and release. All new tool assets load. Clippy remains unavailable; no long-session hands-on balancing is claimed.

## Earlier automated checks

`cargo test --manifest-path rewrite/Cargo.toml --offline` passed all 48 tests. Coverage includes source catalog data, purchases, save replacement/round-trip, body stability and clock/awake branches, source object properties and collisions, explosion rewards/shared velocity, moving bullets/ricochets/head impact, ShockScript semantics and host effects, use/release stability for all 45 catalog items, the capacity-notice channel (object and bullet ceilings warn, notices expire, and they never overwrite an action result), the desktop rail geometry, the rule that only a real click dismisses the open companion panel, word wrapping that preserves embedded newlines and never drops or reorders words, and the interface font selection.

`cargo run --manifest-path rewrite/Cargo.toml --offline -- --smoke-test` passed the classic-window smoke test, driving menu/shop/skin/script actions, asserting a purchase and script-created grenade, and capturing seven screenshots in `rewrite/screenshots/`. Demo state is unsaved.

The Windows desktop smoke test completed 320 frames on a 1920x1032 work area, producing six desktop screenshots; the game stage measured 1280x688. Coverage includes the collapsed corner pair (`desktop-01.png`), the Items panel with both speech and capacity notices stacked above Buddy (`desktop-03.png`), the store window (`desktop-04.png`), and the File and Settings panels reached by switching rail sections (`desktop-05.png`, `desktop-06.png`). Every control on the rail, corner button or section, is drawn by the single `dot` helper in `desktop_ui.rs`, so a control cannot render without also registering its click target. All eight of them — the menu and close buttons plus the six sections — are tinted discs drawn from `circle.png`, each carrying a distinct drawn glyph (hamburger, cross, page, palette, four items, spark, sliders, question mark). `assets/menu/menu_button.png` and `exit_button.png` are no longer loaded; the files remain in the repository unused.

The companion switches are wired to the window rather than only to the picture: Notices are drawn once, as Buddy's speech bubble, by `draw_notices`, which both the overlay path and the classic path call; the duplicate top-of-screen banner and its `wrap` helper are gone. `bubbles_truncate_on_a_word_boundary` covers `ellipsize`, which cuts over-long plates on a word boundary rather than at a fixed character count, and hard-cuts when there is no boundary to cut on.

`blood_and_gore_bleeds_visibly` pins down that the gore mode produces blood a player can see: the old implementation was functionally correct — the mode toggled, the gate `strength > 2` fired, particles spawned — but the droplets had `r: 1.5`, drawn at 0.75-1.5 pixels with no gravity, so the feature looked dead. The test toggles the mode through the real `Action::Select` path and asserts droplets of at least 2px that all travel downward, plus a stationary splat, and that the same hit is clean with the mode off. Its first version asserted the spray fell using a `y` offset that the sideways fan could outweigh, and the test caught the outer droplets still rising; the cone is now aimed down and fanned perpendicular to that axis.

Mouse passthrough forces `WS_EX_TRANSPARENT` outside menu controls; `Ctrl+Alt+P` is a global escape hatch for it. The menu and close buttons are deliberately exempt from that block, and clicking the menu button clears passthrough as well as opening the rail: keeping them live but leaving every icon in the opened rail dead is not an escape route, and `the_menu_button_stays_clickable_in_every_mode` drives the real `desktop_hit` across every combination rather than the menu's own hit test, which is what let an earlier version ship a one-way door that its own test suite called correct. Equipping a weapon arms capture and swallows every click system-wide, menu included, so `Action::Hand` (now **right-click**, replacing H) restores the desktop without needing the menu reachable; `putting_away_tools_always_restores_the_desktop` and `hands_leave_the_desktop_alone` cover both directions, and the desktop smoke test screenshots the paused and restored states. The `show_overlay` and `mouse_passthrough` save fields default to on and off respectively, so an existing save file loads without them. The separate Windows fixture-only window-effects test passed its shake geometry, explosion, minimize, debris, and restore checks. These tests validate the application/update loop and native window-effects path on the tested machine. Desktop mode currently targets the primary monitor only.

The portable executable in `dist/Interactive Buddy/` also completed the desktop smoke test, using assets bundled beside the executable. The package includes a console-free launcher and standalone usage notes.

## What these checks establish

The port builds and runs natively, and the tested controls and state transitions work. Desktop screenshots preserve RGBA: every capture asserts a zero-alpha background corner. The open Items screenshot contains 1,795,891 fully transparent pixels out of 1,981,440, with only Buddy, controls and their shadows drawn. The layout was visually inspected, including Buddy clearance from the menu strip. Input capture has unit coverage and the desktop smoke verifies idle click-through state; physical pointer interaction with other applications still needs hands-on review. These checks do not establish complete visual or behavioral equivalence to Flash. There has not been a frame-by-frame comparison of identical input sequences against the original SWF. Remaining differences are tracked in `rewrite/PARITY.md`; the extracted ActionScript in `decomp/scripts/frame_25/DoAction.as` remains the authoritative local reference.

The updated desktop and contained floating-window smoke tests passed. The native fixture test additionally verified the actual Windows compositor: a transparent overlay pixel exposed the white fixture beneath it, while a red overlay marker remained visible. Weapon regression tests cover bullets and missiles reaching Buddy in front of a window and automatic tool arming. Physical mouse interaction still needs hands-on review.

The window-border contact resolver was removed on request as janky: windows are no longer colliders for the Buddy, and the faint border outlines went with it. Window rectangles are still reported to the companion and still do not block bullets or missiles. The interface font is Segoe UI (regular and semibold) loaded from the system font directory, with the bundled Arial as fallback; both paths are chosen by a helper that checks the sfnt signature, because a font file that fails to parse renders an interface with no text and no error. Loading those two files uses an explicit `override_unapproved` load while the asset plugin stays on `Deny`, so the exemption covers the fonts and nothing else. The shop card, rows, price chips, pager and the transient notice were restyled onto one shared palette; the notice is drawn above the modal card, having previously rendered behind it with only its edges showing. Unit tests no longer inherit the player's save file, and smoke runs are redirected to `smoke-save.json` so they cannot overwrite real progress.
